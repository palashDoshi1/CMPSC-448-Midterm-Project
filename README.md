## Project Overview

This project investigates whether neural network classifiers can identify which large language model (LLM) generated a given text response.

We implement and compare two neural network architectures:

- **Convolutional Neural Network (CNN)**
- **Long Short-Term Memory Network (LSTM)**

Our classification task distinguishes responses generated by three LLM families: **GPT, Claude, and Gemini**.

In addition to basic model identification, we investigate how input selection, task domain, and writing-style characteristics affect classification performance.

The project addresses two required research questions (RQ1 and RQ2) and two extra-credit investigations (RQ3 and RQ4).

## Research Questions

### RQ1 — LLM Identification

Can CNN and LSTM classifiers correctly identify which LLM generated a response? Which architecture performs better?

### RQ2 — Input vs. Output vs. Combined

How does classification performance change when using:

1. The original user prompt only
2. The LLM-generated response only
3. The original prompt and generated response combined

### RQ3 — Cross-Domain Generalization (Extra Credit)

Can classifiers trained on responses from five task categories generalize to a sixth category that was excluded from training?

We investigate this by holding out **general writing** as the unseen domain.

### RQ4 — Writing-Style Analysis (Extra Credit)

What measurable writing-style characteristics distinguish GPT, Claude, and Gemini responses?

We investigate response length, lexical diversity, punctuation, headings, lists, code fences, and other formatting patterns.

## Dataset

Our dataset consists of **180 unique prompts and 540 LLM-generated responses**.

Each prompt was answered once by each of the three LLM families, resulting in a balanced dataset:

- 180 GPT responses
- 180 Claude responses
- 180 Gemini responses

## Text Preprocessing

For the main output-only classification task, both architectures use consistent preprocessing:

- Case-sensitive tokenization
- Punctuation and formatting symbols retained as tokens
- Shared training-derived vocabulary of up to 10,000 tokens
- Padding token `<PAD>` assigned ID 0
- Unknown token `<UNK>` assigned ID 1
- Maximum sequence length of 512 tokens
- Right padding and truncation

### Label Encoding

| Model Family | Label |
|---|---:|
| GPT | 0 |
| Claude | 1 |
| Gemini | 2 |

The shared vocabulary is stored in `data/vocab.json`.

For RQ3, separate source-domain training vocabularies are constructed without using any responses from the held-out general-writing category.

## Model Architectures

### Convolutional Neural Network (CNN)

The CNN extracts local textual patterns using parallel convolutional filters of different sizes.

**Architecture:**

- Embedding dimension: 128
- Convolutional kernel sizes: 3, 5, and 7
- Filters per kernel size: 128
- Pooling over convolutional features
- Dropout: 0.3
- Fully connected classification layer
- Output classes: 3

The CNN uses the Adam optimizer and cross-entropy loss.

For RQ1, the best CNN checkpoint is selected based on **validation loss**.

### Long Short-Term Memory Network (LSTM)

The LSTM models sequential relationships between tokens using a recurrent neural network.

**Architecture:**

- Single-layer, unidirectional LSTM
- Embedding dimension: 128
- Hidden dimension: 128
- Dropout: 0.3, applied after the recurrent layer
- Packed padded sequences
- Final hidden state used for classification
- Fully connected classification layer
- Output classes: 3

The LSTM uses the Adam optimizer and cross-entropy loss.

For RQ1, the best LSTM checkpoint is selected based on **validation macro-F1**.

### Training Configuration

| Parameter | CNN | LSTM |
|---|---|---|
| Embedding dimension | 128 | 128 |
| Maximum sequence length | 512 | 512 |
| Batch size | 16 | 16 |
| Optimizer | Adam | Adam |
| Learning rate | 0.001 | 0.001 |
| Loss function | Cross-entropy | Cross-entropy |
| Dropout | 0.3 | 0.3 |
| Maximum epochs | 20 | 20 |
| Early stopping patience | 4 | 4 |
| Random seed | 42 | 42 |
| RQ1 checkpoint selection | Validation loss | Validation macro-F1 |

Both architectures use early stopping and restore their selected validation checkpoint before final evaluation.

## Experimental Results

### RQ1 — LLM Identification

For RQ1, we trained both architectures to identify the generating LLM using only its generated response.

Both models were evaluated on the same held-out test set of **81 responses**.

| Model | Test Accuracy | Macro-F1 |
|---|---:|---:|
| **CNN** | **82.72%** | **0.8293** |
| LSTM | 71.60% | 0.7141 |

The CNN correctly classified **67 of 81** responses, compared with **58 of 81** for the LSTM.

The CNN outperformed the LSTM by approximately **11.11 percentage points** in test accuracy.

These results suggest that the CNN was more effective at identifying model-specific response patterns under the evaluated experimental configuration.

### RQ2 — Input-Only vs. Output-Only vs. Combined

RQ2 investigates whether the original user prompt, generated response, or their combination provides the most useful information for identifying the generating LLM.

We compared three input configurations:

- **Input-only:** Original user prompt
- **Output-only:** Generated LLM response
- **Combined:** Original prompt and generated response

#### CNN vs. LSTM Results

| Input Configuration | CNN Accuracy | CNN Macro-F1 | LSTM Accuracy | LSTM Macro-F1 |
|---|---:|---:|---:|---:|
| Input-only | 33.33% | 0.3078 | 33.33% | 0.3281 |
| **Output-only** | **82.72%** | **0.8293** | **71.60%** | **0.7141** |
| Combined | 77.78% | 0.7730 | 53.09% | 0.5294 |

#### Findings

**Output-only classification performed best for both architectures.**

The CNN achieved 82.72% accuracy and the LSTM achieved 71.60% when using only the generated response.

**Input-only classification performed at chance level.**

Both architectures achieved 33.33% accuracy, consistent with random guessing among three balanced classes.

This is expected because the same prompts were submitted to all three LLM families. The prompt alone does not contain information about which model generated the corresponding response.

**Combining prompts and responses did not improve performance.**

The CNN achieved 77.78% accuracy with combined input, compared with 82.72% using output only.

The LSTM achieved 53.09% with combined input, compared with 71.60% using output only.

A possible explanation is that adding the original prompt introduces content unrelated to model-specific writing patterns. However, this explanation was not established through a separate causal experiment.

### RQ3 — Cross-Domain Generalization (Extra Credit)

RQ3 evaluates whether CNN and LSTM classifiers trained on five source categories can identify LLM responses from a previously unseen sixth category.

**Held-out category:** `general_writing`

The five source categories were:

- `cs_software`
- `finance_banking`
- `math_logic`
- `sports`
- `stocks_trading`

For this experiment:

1. New CNN and LSTM classifiers were trained without general-writing responses.
2. General writing was excluded from both training and validation.
3. Experiment-specific vocabularies were built using source-domain training responses only.
4. Both classifiers were evaluated on all **90 general-writing responses**, including 30 from each LLM family.

#### CNN — Source vs. Unseen Domain

| Evaluation Set | Responses | Accuracy | Macro-F1 |
|---|---:|---:|---:|
| Source-domain test | 66 | 89.39% | 0.8932 |
| Unseen general writing | 90 | 72.22% | 0.7161 |

The CNN's accuracy decreased by **17.17 percentage points** when evaluated on the unseen general-writing category.

The best CNN RQ3 checkpoint was selected at epoch 6 using validation macro-F1.

#### LSTM — Source vs. Unseen Domain

| Evaluation Set | Responses | Accuracy | Macro-F1 |
|---|---:|---:|---:|
| Source-domain test | 66 | 51.52% | 0.4890 |
| Unseen general writing | 90 | 56.67% | 0.5429 |

The LSTM achieved slightly higher accuracy on the unseen general-writing domain than on its source-domain test set.

Therefore, the LSTM did not exhibit an accuracy decrease between these two evaluation sets, although its overall performance was lower than the CNN's.

The best LSTM RQ3 checkpoint was selected at epoch 12 using validation macro-F1.

#### CNN vs. LSTM — Unseen-Domain Comparison

| Model | Responses | Accuracy | Macro-F1 |
|---|---:|---:|---:|
| **CNN** | 90 | **72.22%** | **0.7161** |
| LSTM | 90 | 56.67% | 0.5429 |

The CNN correctly classified **65 of 90** general-writing responses, while the LSTM correctly classified **51 of 90**.

The CNN outperformed the LSTM by approximately **15.56 percentage points** in unseen-domain accuracy and **0.1732** in macro-F1.

#### LSTM Class-Level Results

| Model Family | Precision | Recall | F1-Score |
|---|---:|---:|---:|
| GPT | 0.65 | 0.43 | 0.52 |
| Claude | 0.77 | 0.33 | 0.47 |
| Gemini | 0.49 | 0.93 | 0.64 |

The LSTM showed a strong tendency to predict Gemini.

Gemini recall reached 0.93, whereas GPT and Claude recall were 0.43 and 0.33, respectively.

This indicates that the LSTM correctly recognized many Gemini responses but also incorrectly classified some GPT and Claude responses as Gemini.

#### Interpretation

Both models performed above the three-class chance baseline on unseen general-writing responses.

The CNN achieved substantially higher accuracy and macro-F1 than the LSTM on this held-out category.

However, these findings are specific to the evaluated dataset and held-out domain. They do not establish that CNNs universally generalize better than LSTMs.

### RQ4 — Writing-Style Analysis (Extra Credit)

RQ4 investigates measurable differences in the writing styles of GPT, Claude, and Gemini.

We analyzed all **540 responses**, with 180 responses per model family.

The analysis considered:

- Response length
- Lexical diversity
- Punctuation and symbol usage
- Heading markers
- List markers
- Code fences
- Bold formatting

#### Writing-Style Measurements

| Measurement | GPT | Claude | Gemini |
|---|---:|---:|---:|
| Mean response length (words) | 459.27 | 629.71 | 328.78 |
| Mean lexical diversity (MATTR-50) | 0.8592 | 0.8259 | 0.8625 |
| Punctuation/symbols per 100 words | 26.53 | 26.00 | 41.25 |
| Responses with heading markers (%) | 30.56 | 0.56 | 39.44 |
| Responses with list markers (%) | 19.44 | 61.67 | 33.33 |
| Responses with code fences (%) | 5.00 | 0.00 | 23.89 |
| Responses with bold markers (%) | 25.56 | 19.44 | 46.67 |

Lexical diversity was measured using the **moving-average type-token ratio with 50-word windows (MATTR-50)**.

This metric reduces the dependence on response length compared with ordinary type-token ratio.

#### Main Observations

**Claude**

- Produced the longest responses on average, approximately 630 words.
- Used list markers most frequently, appearing in 61.67% of responses.
- Had the lowest mean MATTR-50 lexical-diversity score.

**Gemini**

- Produced the shortest responses on average, approximately 329 words.
- Used heading markers most frequently, appearing in 39.44% of responses.
- Used code fences most frequently, appearing in 23.89% of responses.
- Had the highest punctuation/symbol count per 100 words.

**GPT**

- Produced responses averaging approximately 459 words.
- Used heading markers in 30.56% of responses.
- Had lexical diversity close to Gemini.

#### Interpretation

The analysis revealed measurable differences in response length, formatting, and punctuation across the three model families.

These characteristics may provide useful signals for model-identification classifiers.

However, this analysis is descriptive. It does not prove that the CNN or LSTM relied on these particular features, and no separate feature-ablation or statistical-significance experiments were conducted.

## Limitations

This project has several limitations:

- The dataset contains 540 responses from only three LLM families.
- Results may depend on the selected prompts, task categories, response lengths, model versions, and collection conditions.
- Different model versions or generation settings may produce different writing styles.
- The classifiers may learn superficial formatting or length-related patterns rather than robust authorship characteristics.
- RQ3 evaluates one held-out category rather than a complete six-domain leave-one-out experiment.
- Source-domain and unseen-domain evaluations differ in sample size and task composition.
- RQ4 is a descriptive analysis and does not establish causality.
- Classifier predictions identify statistical patterns and do not prove authorship with certainty.
