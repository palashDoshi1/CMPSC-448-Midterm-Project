# Who Wrote It? Identifying LLMs from Their Responses

**CMPSC 448 — Midterm Project**

**Team Members:** Palash Doshi (Team Leader) and Siddharth Pendyala

## Project Overview

This project investigates whether machine learning classifiers can identify which large language model (LLM) generated a given text response.

We compare two neural network architectures:

- **Convolutional Neural Network (CNN)**
- **Long Short-Term Memory Network (LSTM)**

The classification task distinguishes responses generated by three LLM families: **GPT, Claude, and Gemini**.

Beyond basic model identification, we investigate how input selection, task domain, and writing-style characteristics affect classification performance.

## Research Questions

**RQ1 — LLM Identification**

Can a neural network correctly identify the generating LLM using only its response? How do CNN and LSTM classifiers compare?

**RQ2 — Input vs. Output vs. Combined**

How does classification performance change when using only the original prompt, only the generated response, or both together?

**RQ3 — Cross-Domain Generalization (Extra Credit)**

Can a classifier trained on responses from five task categories generalize to responses from an unseen sixth category?

**RQ4 — Writing-Style Analysis (Extra Credit)**

What measurable writing-style differences exist between the three LLM families, and how might those differences help explain classification performance?

## Dataset

Our dataset contains **540 LLM-generated responses** corresponding to **180 unique prompts**.

Each prompt was answered once by each of the three LLM families, producing a balanced dataset with 180 responses per family.

The prompts span six categories:

| Category | Number of Prompts |
|---|---:|
| Sports | 30 |
| Stocks and Trading | 30 |
| Finance and Banking | 30 |
| Computer Science and Software | 30 |
| Mathematics and Logic | 30 |
| General Writing | 30 |
| **Total** | **180** |

### Data Splitting

For the main classification experiments, the dataset was split by prompt ID rather than individual response. This prevents responses to the same prompt from appearing in different partitions.

| Split | Prompts | Responses |
|---|---:|---:|
| Training | 126 | 378 |
| Validation | 27 | 81 |
| Testing | 27 | 81 |

A fixed random seed of 42 was used for reproducibility.

## Preprocessing

Both CNN and LSTM use consistent preprocessing for the main output-only classification task:

- Case-sensitive tokenization preserving punctuation and formatting tokens
- Shared training-derived vocabulary of up to 10,000 tokens
- `<PAD>` token ID 0 and `<UNK>` token ID 1
- Maximum sequence length of 512 tokens
- Right padding and truncation
- Label encoding: GPT = 0, Claude = 1, Gemini = 2

For RQ3, the held-out domain is excluded when constructing the experiment-specific vocabulary.

## Model Architectures

### CNN

The CNN uses 128-dimensional token embeddings, parallel convolutional filters with kernel sizes 3, 5, and 7, pooling, and a classification layer to predict the generating model family.

### LSTM

The LSTM uses:

| Parameter | Value |
|---|---|
| Architecture | Single-layer, unidirectional LSTM |
| Embedding dimension | 128 |
| Hidden dimension | 128 |
| Dropout | 0.3 |
| Maximum sequence length | 512 |
| Batch size | 16 |
| Optimizer | Adam |
| Learning rate | 0.001 |
| Loss function | Cross-entropy |
| Maximum epochs | 20 |
| Early stopping patience | 4 |
| Random seed | 42 |

The LSTM uses packed padded sequences and the final hidden state for three-class classification.

## Experimental Results

### RQ1 — Output-Only Classification

Both architectures were evaluated on the same held-out set of 81 responses.

| Model | Test Accuracy | Macro-F1 |
|---|---:|---:|
| **CNN** | **82.72%** | **0.8293** |
| LSTM | 71.60% | 0.7141 |

The CNN outperformed the LSTM by approximately **11.11 percentage points** in test accuracy.

### RQ2 — Input Selection

LSTM results:

| Input Configuration | Test Accuracy | Macro-F1 |
|---|---:|---:|
| Input-only | 33.33% | 0.3281 |
| **Output-only** | **71.60%** | **0.7141** |
| Combined input + output | 53.09% | 0.5294 |

Output-only classification achieved the highest performance among the three configurations.

Input-only classification performed approximately at the 33.33% chance baseline, consistent with the fact that all three model families received the same prompts.

### RQ3 — Cross-Domain Generalization

For this experiment, general writing was held out entirely from model training and validation.

The classifiers were trained using the other five categories and evaluated on all **90 general-writing responses** (30 per model family).

| Model | Unseen-Domain Accuracy | Macro-F1 |
|---|---:|---:|
| **CNN** | **72.22%** | **0.7161** |
| LSTM | 56.67% | 0.5429 |

The CNN outperformed the LSTM by approximately **15.56 percentage points** on the unseen general-writing domain.

The LSTM showed a tendency to predict Gemini disproportionately. Its Gemini recall was 0.93, compared with 0.43 for GPT and 0.33 for Claude.

These findings suggest that the CNN learned more transferable classification patterns for this held-out category. However, the experiment examines one unseen domain rather than all possible domain combinations.

### RQ4 — Writing-Style Analysis

We additionally investigate writing-style characteristics such as:

- Response length and token counts
- Formatting and Markdown usage
- Headings and structural organization
- Punctuation patterns
- Vocabulary characteristics

This analysis is intended to identify measurable stylistic differences among GPT, Claude, and Gemini and relate them to classification performance.

Detailed RQ4 findings are presented in `CNN.ipynb` and the final project report.

## Key Findings

1. CNN achieved higher output-only classification accuracy than LSTM.
2. Generated responses contained more useful model-identification information than the original prompts.
3. Both architectures demonstrated above-chance accuracy on the unseen general-writing domain.
4. LSTM predictions exhibited a noticeable bias toward Gemini in the unseen-domain evaluation.
5. Generalization performance varied across architectures, emphasizing the importance of evaluating beyond the training domains.

## Limitations

The dataset contains only 540 responses from three LLM families. Results may depend on response length, prompt categories, model versions, and collection conditions.

The cross-domain experiment uses general writing as the held-out category and therefore does not establish generalization across every possible unseen domain.

The project identifies patterns in generated text rather than proving authorship with certainty.
