## Project Overview

We investigate whether neural-network classifiers can identify which large language model (LLM) generated a response. We compare a **Convolutional Neural Network (CNN)** and a **Long Short-Term Memory (LSTM)** classifier on text generated by three LLM families: **GPT, Claude, and Gemini**.

For original response collection, we used **GPT-6 Instant**, **Claude Sonnet 5.5**, and **Gemini 1.5 Pro**, as documented by the project team. Our research covers response-only identification (RQ1), the role of user prompts (RQ2), transfer to an unseen subject category (RQ3), and measurable writing-style differences (RQ4). The first three questions are implemented in the CNN and LSTM notebooks. **RQ4 is a separate descriptive-analysis notebook developed jointly by both team members; it does not train another classifier.**

## Research Questions

- **RQ1 — LLM identification:** Can a CNN or LSTM identify the source LLM from the generated response alone? Which achieves higher classification performance?
- **RQ2 — Input, output, or combined:** How do the models perform using the original prompt only, the generated response only, or both together?
- **RQ3 — Cross-domain generalization (extra credit):** Can classifiers trained without *general writing* identify model-generated responses in that held-out category?
- **RQ4 — Writing-style analysis (extra credit):** What differences in response length, lexical diversity, punctuation, and Markdown-like formatting appear across GPT, Claude, and Gemini?

## Classification Preprocessing

The CNN and LSTM use case-sensitive tokenization with the Python regular expression `r"\w+|[^\w\s]"`, separating word runs and individual punctuation/symbol characters. Whitespace and line breaks are not represented as explicit tokens.

- Vocabulary limited to **10,000 tokens**, selected from the training portion of the corresponding experiment only; validation and test text are excluded.
- Padding token `<PAD>` = **0**; unknown token `<UNK>` = **1**.
- Sequences padded or truncated to **512 tokens**.
- Class labels: **GPT = 0**, **Claude = 1**, **Gemini = 2**.
- RQ1 uses a shared training-derived output-only vocabulary. RQ2 constructs separate input-only and combined-input vocabularies from training text. RQ3 constructs a source-domain training-only vocabulary, excluding general writing.

**RQ2 input configurations:**

1. **Input-only:** user prompt.
2. **Output-only:** generated response.
3. **Combined:** up to **128 prompt tokens**, one `[SEP]` token, and up to **383 response tokens**.

Unused prompt capacity was **not transferred to the response**. Thus, combined-input experiments retained up to 383 response tokens versus 512 in output-only experiments. This matters when interpreting differences between those configurations.

## Models and Training

### CNN — Palash Doshi

The TextCNN uses a 128-dimensional embedding layer, parallel 1D convolutions with kernel sizes **3, 5, and 7** (128 filters per branch), ReLU activations, padding-aware global max pooling, and a concatenated **384-dimensional** representation. A **0.3 dropout** layer precedes the final three-class linear classifier. Padded positions are masked before global max pooling.

### LSTM — Siddharth Pendyala

The LSTM uses 128-dimensional embeddings, a **single-layer unidirectional LSTM** with **128 hidden units**, packed padded sequences, and the **final hidden state** as the classification representation. Dropout is **0.3** before the three-class output layer.

## Experimental Results

### RQ1 — Identify the generating LLM from its response

The held-out test set contains **81 responses** (27 per LLM family).

| Model | Test accuracy | Macro-F1 | Correct predictions |
|---|---:|---:|---:|
| **CNN** | **82.72%** | **0.8293** | **67/81** |
| LSTM | 71.60% | 0.7141 | 58/81 |
| Balanced three-class baseline | 33.33% | — | — |

The CNN's observed accuracy exceeds the LSTM's by about **11.11 percentage points**. Both models performed above the balanced baseline. The performance gap is **descriptive, not a statistically established difference**; different RQ1 checkpoint criteria and the limited single-split evaluation should be considered.

### RQ2 — Input-only vs. output-only vs. combined

| Input configuration | CNN accuracy | CNN macro-F1 | LSTM accuracy | LSTM macro-F1 |
|---|---:|---:|---:|---:|
| Input-only | 33.33% | 0.3078 | 33.33% | 0.3281 |
| **Output-only** | **82.72%** | **0.8293** | **71.60%** | **0.7141** |
| Combined input/output | 77.78% | 0.7730 | 53.09% | 0.5294 |

**Why is input-only accuracy exactly 33.33%?** Each of the 27 held-out prompts has one GPT, one Claude, and one Gemini label. A deterministic classifier receiving the same prompt text three times must produce the same prediction each time, giving exactly **one correct prediction per prompt group**, or **27/81 correct**. The resulting accuracy equals the chance baseline, but the predictions do **not** need to be random. The different macro-F1 scores reflect different prediction distributions among the three classes.

**Why did combined input score lower?** Output-only had the highest observed accuracy for both architectures, but the experiment did **not** isolate the effect of prompt inclusion. In addition to introducing the prompt, combined input reduced the response budget from 512 to 383 tokens, used a separately built vocabulary, and, for the CNN, used a different checkpoint-selection criterion. We therefore **cannot conclude that adding the prompt itself caused the decline**. A controlled follow-up would hold those factors constant.

### RQ3 — Cross-domain generalization

The five training domains were computer science/software, finance/banking, mathematics/logic, sports, and stocks/trading. We **excluded general writing from training, validation, and vocabulary construction**. Each notebook removed general-writing rows from the shared predefined partitions, preserving the same remaining prompt assignments.

| Partition | Responses |
|---|---:|
| Source-domain training | 315 |
| Source-domain validation | 69 |
| Source-domain test | 66 |
| Unseen general-writing test | 90 |

All **90 general-writing responses** (30 per LLM family) formed the held-out-domain evaluation set.

| Evaluation | CNN accuracy | CNN macro-F1 | LSTM accuracy | LSTM macro-F1 |
|---|---:|---:|---:|---:|
| Source-domain test | 89.39% | 0.8932 | 51.52% | 0.4890 |
| **Unseen general writing** | **72.22%** | **0.7161** | 56.67% | 0.5429 |
| Accuracy change (source to unseen) | **−17.17 pp** | — | **+5.15 pp** | — |

The CNN correctly classified **65/90** unseen responses and the LSTM correctly classified **51/90**. The CNN experienced a decrease relative to its own source-domain score, while the LSTM increased slightly from a weaker source-domain baseline. These are **within-RQ3** comparisons; RQ1 and RQ3 used separate training configurations. The difference between architectures was not tested for statistical significance.

### RQ4 — Descriptive writing-style analysis (separate notebook)

Both team members jointly developed a standalone notebook to analyze all **540 complete, untruncated stored responses**. No additional classifier was trained for RQ4.

| Measurement | GPT | Claude | Gemini |
|---|---:|---:|---:|
| Mean response length (words) | 459.27 | 629.71 | 328.78 |
| Mean lexical diversity (MATTR-50) | 0.8592 | 0.8259 | 0.8625 |
| Mean punctuation/symbols per 100 words | 26.53 | 26.00 | 41.25 |
| Responses with heading markers | 30.56% | 0.56% | 39.44% |
| Responses with list markers | 19.44% | 61.67% | 33.33% |
| Responses with code fences | 5.00% | 0.00% | 23.89% |
| Responses with bold markers | 25.56% | 19.44% | 46.67% |

#### How RQ4 measurements were calculated

- **Words:** Python Unicode-aware regex `r"\b\w+\b"` on each stored response, including code and Markdown. Numbers and code identifiers may contribute to the count; this differs from the classification tokenizer.
- **MATTR-50:** Extracted words were lowercased. The ratio of distinct words to 50 words was computed over each successive 50-word window, then averaged per response. The model-level figure is the unweighted mean of eligible responses. One GPT response had fewer than 50 words; MATTR-50 sample sizes were **179 GPT, 180 Claude, and 180 Gemini**.
- **Punctuation/symbols per 100 words:** Count of characters matching `r"[^\w\s]"`, divided by each response's word count and multiplied by 100. The reported value is the unweighted average of those per-response rates.
- **Formatting:** Simple pattern checks, not a complete Markdown parser. Heading lines match `r"^\s{0,3}#{1,6}\s+"`; list lines match `r"^\s*(?:[-*+]|\d+[.)])\s+"`. Code fences are detected by ` ``` ` or `~~~`; bold markers by `**` or `__`. The percentage is the fraction of each model's **180 responses** containing at least one marker, not a count of individual occurrences. Marker checks could also match text inside code.

Claude produced the longest responses and the highest share of list-marked responses. Gemini had the highest observed frequencies of headings, code fences, bold markers, and punctuation/symbols per 100 words. These are **descriptive associations**, not evidence that the CNN or LSTM relied on any particular feature. The results correspond to **Table 10 and Figures 13–14** in the report.

## Limitations

- **Small and narrow dataset:** 540 responses from only three LLM families and six selected subject categories.
- **Collection reproducibility:** Manual copy-and-paste collection; full conversation-reset, generation-setting, and cleaning logs were not retained.
- **Split and environment records:** Shared partition CSVs preserve the assignments, but the original split-generation seed and complete original software/hardware versions are unavailable.
- **Single evaluation:** One predefined prompt-grouped split and one recorded training run per configuration. Test responses sharing a prompt are related observations.
- **Uncertainty:** Confidence intervals and statistical-significance tests were not computed. Reported performance differences are descriptive; future paired uncertainty analyses should account for prompt groups.
- **RQ2 confounding:** Prompt inclusion was accompanied by changes in response-token budget and vocabulary, and in one comparison checkpoint selection; its independent effect was not isolated.
- **Domain coverage:** Only general writing was held out in RQ3. Results do not establish generalization to every subject area.
- **Interpretability:** RQ4 shows descriptive text differences, not which features caused individual classifier predictions.
- **Authorship certainty:** Model predictions are statistical classifications, not definitive proof of authorship.

## Future Work

Future experiments could expand the prompt set and model versions, compare transformer-based classifiers, run multiple training seeds and alternative grouped splits, and evaluate each held-out category in turn. For RQ2, a controlled follow-up should hold the response-token budget, training-derived vocabulary, and checkpoint selection constant. Feature-ablation and attribution studies could test whether the differences identified in RQ4 affect classifier decisions.

## Conclusion

On the primary response-only task, the CNN achieved **82.72%** accuracy and the LSTM achieved **71.60%**. Prompt-only accuracy was exactly **33.33%** under the balanced repeated-prompt design. Combined prompt-response inputs performed worse under a different token allocation, so the independent effect of adding prompts remains unresolved. On unseen general-writing responses, the CNN achieved **72.22%** and the LSTM **56.67%**. The standalone RQ4 analysis identified measurable differences in stored response length, lexical diversity, punctuation, and formatting.

These results demonstrate learnable source-related patterns in this dataset, while the limited sample size, uncontrolled generation details, evaluation uncertainty, and domain constraints restrict broader authorship claims.
