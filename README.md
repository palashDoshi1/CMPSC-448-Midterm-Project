## Project Overview

This project investigates whether neural-network classifiers can identify which large language model (LLM) generated a text response.

We implemented and compared two neural-network architectures:

- **Convolutional Neural Network (CNN)**
- **Long Short-Term Memory Network (LSTM)**

Our classification task distinguishes responses generated by three LLM families: **GPT, Claude, and Gemini**.

For dataset collection, we used the following model versions:

- **GPT-6 Instant**
- **Claude Sonnet 5.5**
- **Gemini 1.5 Pro**

The project examines whether these models exhibit identifiable linguistic, structural, and stylistic patterns in their generated responses.

Beyond basic classification, we investigate whether the original user prompt improves identification, whether learned patterns generalize to an unseen subject category, and which measurable writing characteristics distinguish the three LLM families.

The project addresses two required research questions (RQ1 and RQ2) and two extra-credit investigations (RQ3 and RQ4).

## Research Questions

### RQ1 — LLM Identification

Can CNN and LSTM classifiers correctly identify which LLM generated a response? Which architecture performs better?

We evaluate whether generated responses alone contain sufficient information to distinguish GPT, Claude, and Gemini.

### RQ2 — Input vs. Output vs. Combined

How does classification performance change when using:

1. The original user prompt only (input-only)
2. The LLM-generated response only (output-only)
3. The original prompt and generated response together (combined input/output)

This experiment investigates whether including the user's original prompt improves model identification.

### RQ3 — Cross-Domain Generalization (Extra Credit)

Can classifiers trained on responses from five task categories generalize to a sixth category excluded from training?

We investigate this by holding out **general writing** as the unseen evaluation domain.

### RQ4 — Writing-Style Analysis (Extra Credit)

What measurable linguistic and structural characteristics distinguish GPT, Claude, and Gemini responses?

We examine response length, lexical diversity, punctuation, heading markers, list markers, code fences, and bold formatting.

## Dataset

We constructed an original dataset containing **180 unique prompts and 540 LLM-generated responses**.

Each prompt was submitted to all three LLM families, producing one response from each model.

The resulting dataset is balanced:

- **180 GPT responses**
- **180 Claude responses**
- **180 Gemini responses**

### Dataset Categories

| Category | Prompts | GPT | Claude | Gemini | Total Responses |
|---|---:|---:|---:|---:|---:|
| Computer Science and Software | 30 | 30 | 30 | 30 | 90 |
| Finance and Banking | 30 | 30 | 30 | 30 | 90 |
| Mathematics and Logic | 30 | 30 | 30 | 30 | 90 |
| Sports | 30 | 30 | 30 | 30 | 90 |
| Stocks and Trading | 30 | 30 | 30 | 30 | 90 |
| General Writing | 30 | 30 | 30 | 30 | 90 |
| **Total** | **180** | **180** | **180** | **180** | **540** |

The dataset includes technical, quantitative, factual, and open-ended writing tasks.

Using identical prompts across the three LLMs allows us to compare their generated responses under similar task conditions.

### Dataset Structure

Each dataset record contains five fields:

| Field | Description |
|---|---|
| `prompt_id` | Unique identifier for the original prompt |
| `category` | Subject category |

The `model` column is the target label for supervised classification.

### Training, Validation, and Test Splits

For RQ1 and RQ2, we divided the dataset into training, validation, and test sets using **prompt-grouped splitting**.

All three responses associated with the same original prompt were assigned to the same partition. This prevents responses to the same prompt from appearing across training and evaluation sets.

| Split | Prompts | Responses | Percentage |
|---|---:|---:|---:|
| Training | 126 | 378 | 70% |
| Validation | 27 | 81 | 15% |
| Testing | 27 | 81 | 15% |
| **Total** | **180** | **540** | **100%** |

The same predefined partitions were used for the primary CNN and LSTM experiments.

We used random seed **42** for reproducibility.

## Text Preprocessing

Before model training, text responses were converted into numerical token sequences.

The main preprocessing configuration included:

- Case-sensitive tokenization
- Word and punctuation token separation
- Preservation of punctuation and formatting-related symbols
- Training-derived vocabulary containing up to 10,000 tokens
- Padding token `<PAD>` assigned ID 0
- Unknown token `<UNK>` assigned ID 1
- Maximum sequence length of 512 tokens
- Sequence padding and truncation

The primary RQ1 models used a shared training-derived vocabulary.

### Label Encoding

| LLM Family | Class Label |
|---|---:|
| GPT | 0 |
| Claude | 1 |
| Gemini | 2 |

### Input Representations

The research questions required different text representations.

**Output-only:** Uses only the generated response.

**Input-only:** Uses only the original user prompt.

**Combined input/output:** Uses both the prompt and generated response, separated by a special `[SEP]` token.

For the combined-input experiments, the 512-token representation allocated:

- Up to 128 tokens for the original prompt
- One separator token
- Up to 383 tokens for the generated response

This allocation allowed both text components to be represented within the fixed sequence-length limit.

For RQ3, separate vocabularies were constructed using only source-domain training responses, excluding the held-out general-writing category.

## Model Architectures

### Convolutional Neural Network (CNN)

**Implemented by:** Palash Doshi

The CNN uses a TextCNN architecture to identify local textual patterns within tokenized responses.

The architecture consists of an embedding layer, parallel convolutional branches, max pooling, dropout, and a fully connected classification layer.

**CNN configuration:**

| Component | Configuration |
|---|---|
| Embedding dimension | 128 |
| Convolutional kernel sizes | 3, 5, 7 |
| Filters per kernel size | 128 |
| Feature extraction | Parallel 1D convolutions |
| Pooling | Padding-aware global max pooling |
| Combined feature dimension | 384 |
| Dropout | 0.3 |
| Output classes | 3 |

The convolutional branches capture local token patterns of different lengths.

The resulting features are concatenated and passed through dropout and a final classification layer.

For RQ1, the best CNN checkpoint was selected using **validation loss**.

### Long Short-Term Memory Network (LSTM)

**Implemented by:** Siddharth Pendyala

The LSTM processes token sequences sequentially and learns representations influenced by previously encountered tokens.

**LSTM configuration:**

| Component | Configuration |
|---|---|
| Embedding dimension | 128 |
| Architecture | Single-layer LSTM |
| Directionality | Unidirectional |
| Hidden dimension | 128 |
| Sequence handling | Packed padded sequences |
| Classification representation | Final hidden state |
| Dropout | 0.3, applied after LSTM |
| Output classes | 3 |

For RQ1, the best LSTM checkpoint was selected using **validation macro-F1**.

### Training Configuration

Both architectures were implemented using Python and PyTorch.

| Hyperparameter | CNN | LSTM |
|---|---|---|
| Optimizer | Adam | Adam |
| Learning rate | 0.001 | 0.001 |
| Loss function | Cross-entropy | Cross-entropy |
| Batch size | 16 | 16 |
| Maximum epochs | 20 | 20 |
| Early stopping patience | 4 | 4 |
| Embedding dimension | 128 | 128 |
| Dropout | 0.3 | 0.3 |
| Maximum sequence length | 512 | 512 |
| Random seed | 42 | 42 |
| RQ1 checkpoint selection | Validation loss | Validation macro-F1 |

Early stopping was used to select model checkpoints based on validation performance rather than simply using the final training epoch.

For RQ1, the selected CNN checkpoint occurred at **epoch 9**, while the selected LSTM checkpoint occurred at **epoch 5**.

## Evaluation Metrics

We evaluated classification performance using:

- **Accuracy:** Proportion of correctly classified responses.
- **Precision:** Proportion of predictions for a class that were correct.
- **Recall:** Proportion of actual examples from a class correctly identified.
- **Macro-F1:** Average of the class-specific F1 scores, giving GPT, Claude, and Gemini equal weight.
- **Confusion matrices:** Class-level summaries of correct predictions and misclassifications.

Macro-F1 was particularly useful for examining whether performance was consistent across all three LLM families.

## Experimental Results

### RQ1 — LLM Identification

For RQ1, both models were trained to identify the generating LLM using only its response.

Both architectures were evaluated on the same held-out test set containing **81 responses**, with 27 responses from each model family.

| Model | Test Accuracy | Macro-F1 | Correct Predictions |
|---|---:|---:|---:|
| **CNN** | **82.72%** | **0.8293** | **67/81** |
| LSTM | 71.60% | 0.7141 | 58/81 |
| Chance baseline | 33.33% | — | — |

The CNN outperformed the LSTM by approximately **11.11 percentage points** in accuracy.

Both models achieved performance substantially above the three-class chance baseline.

These results suggest that generated responses contain learnable patterns associated with their source LLM families.

The CNN's stronger performance indicates that local textual patterns were particularly effective under our experimental conditions.

However, the results do not establish that CNNs are universally superior to LSTMs for authorship classification.

### RQ2 — Input-Only vs. Output-Only vs. Combined

RQ2 investigates whether the original user prompt provides useful additional information for identifying the generating LLM.

We evaluated three configurations using both architectures.

| Input Configuration | CNN Accuracy | CNN Macro-F1 | LSTM Accuracy | LSTM Macro-F1 |
|---|---:|---:|---:|---:|
| Input-only | 33.33% | 0.3078 | 33.33% | 0.3281 |
| **Output-only** | **82.72%** | **0.8293** | **71.60%** | **0.7141** |
| Combined input/output | 77.78% | 0.7730 | 53.09% | 0.5294 |

#### Main Findings

**Output-only classification achieved the highest accuracy for both architectures.**

The CNN achieved 82.72% accuracy and the LSTM achieved 71.60% when using only generated responses.

**Input-only classification performed at the chance baseline.**

Both architectures achieved 33.33% accuracy when using only the original prompts.

This result is consistent with the dataset design because each prompt was submitted to all three LLM families. The prompt itself therefore does not uniquely identify which model generated the corresponding response.

**Combining prompts with responses did not improve performance.**

The CNN achieved 77.78% accuracy using combined input, compared with 82.72% using output-only input.

The LSTM achieved 53.09% accuracy using combined input, compared with 71.60% using output-only input.

One possible explanation is that adding the prompt introduced information unrelated to the generating model's writing characteristics. The combined-input token allocation also limited the response portion to 383 tokens rather than the full 512-token output-only sequence.

However, these possible explanations were not isolated through separate causal experiments.

Overall, RQ2 demonstrates that the generated response was the most informative input for identifying the source LLM under our experimental conditions.

### RQ3 — Cross-Domain Generalization (Extra Credit)

RQ3 examines whether models trained on five subject categories can classify responses from a sixth, previously unseen category.

We selected **general writing** as the held-out domain.

The five source categories were:

- Computer Science and Software
- Finance and Banking
- Mathematics and Logic
- Sports
- Stocks and Trading

The general-writing category was completely excluded from training and validation.

Fresh CNN and LSTM classifiers were trained using the five source categories. Experiment-specific vocabularies were constructed using source-domain training data only.

#### Cross-Domain Dataset Splits

| Dataset Partition | Responses |
|---|---:|
| Source-domain training | 315 |
| Source-domain validation | 69 |
| Source-domain testing | 66 |
| Unseen general-writing testing | 90 |

Both architectures used the same source-domain partition sizes and were evaluated on the same 90 general-writing responses.

The unseen-domain evaluation contained 30 responses from each LLM family.

#### CNN Cross-Domain Results

| Evaluation Set | Responses | Accuracy | Macro-F1 |
|---|---:|---:|---:|
| Source-domain test | 66 | 89.39% | 0.8932 |
| Unseen general writing | 90 | 72.22% | 0.7161 |

The CNN correctly classified **65 of 90** unseen general-writing responses.

Its accuracy decreased by **17.17 percentage points** between the source-domain and unseen-domain evaluations.

The CNN's best RQ3 checkpoint was selected at **epoch 6** using validation macro-F1.

The unseen-domain confusion matrix showed differences in class-specific performance:

- GPT recall: 90.00%
- Claude recall: 46.67%
- Gemini recall: 80.00%

Fourteen Claude responses were incorrectly classified as GPT.

These results suggest that distinguishing Claude from GPT was particularly challenging for the CNN in the unseen general-writing domain.

#### LSTM Cross-Domain Results

| Evaluation Set | Responses | Accuracy | Macro-F1 |
|---|---:|---:|---:|
| Source-domain test | 66 | 51.52% | 0.4890 |
| Unseen general writing | 90 | 56.67% | 0.5429 |

The LSTM correctly classified **51 of 90** unseen general-writing responses.

Unlike the CNN, the LSTM did not experience an accuracy decrease between its source-domain and unseen-domain evaluations. Its accuracy increased by approximately **5.15 percentage points**, although overall performance remained relatively weak.

The best LSTM RQ3 checkpoint was selected at **epoch 12** using validation macro-F1.

#### LSTM Class-Level Results on Unseen General Writing

| Model Family | Precision | Recall | F1-Score |
|---|---:|---:|---:|
| GPT | 0.65 | 0.43 | 0.52 |
| Claude | 0.77 | 0.33 | 0.47 |
| Gemini | 0.49 | 0.93 | 0.64 |

The LSTM showed a strong tendency to predict Gemini.

Gemini recall reached approximately 93%, while GPT and Claude recall were approximately 43% and 33%, respectively.

This indicates that the LSTM successfully recognized many Gemini responses but frequently assigned GPT and Claude responses to the wrong class.

#### CNN vs. LSTM Cross-Domain Comparison

| Metric | CNN | LSTM |
|---|---:|---:|
| Source-domain test accuracy | 89.39% | 51.52% |
| Unseen-domain accuracy | **72.22%** | 56.67% |
| Unseen-domain macro-F1 | **0.7161** | 0.5429 |
| Source-to-target accuracy change | −17.17 pp | +5.15 pp |

The CNN outperformed the LSTM by approximately **15.56 percentage points** on the unseen general-writing domain.

Both architectures performed above the three-class chance baseline on the unseen category.

However, the results also show that cross-domain behavior differed by architecture. The CNN maintained stronger overall accuracy but experienced a decline relative to its source-domain performance. The LSTM showed a small increase but remained substantially less accurate.

These findings are specific to the evaluated models, dataset, and held-out category.

### RQ4 — Writing-Style Analysis (Extra Credit)

RQ4 investigates measurable linguistic and structural differences among GPT, Claude, and Gemini responses.

Unlike RQ1–RQ3, which focused on supervised classification performance, RQ4 used descriptive measurements to examine the writing characteristics of the generated text.

The analysis included **all 540 responses**, with 180 responses from each LLM family.

We examined:

- Response length
- Lexical diversity
- Punctuation and symbol frequency
- Heading markers
- List markers
- Code fences
- Bold formatting markers

#### Quantitative Writing-Style Results

| Measurement | GPT | Claude | Gemini |
|---|---:|---:|---:|
| Mean response length (words) | 459.27 | 629.71 | 328.78 |
| Mean lexical diversity (MATTR-50) | 0.8592 | 0.8259 | 0.8625 |
| Punctuation/symbols per 100 words | 26.53 | 26.00 | 41.25 |
| Responses with heading markers (%) | 30.56 | 0.56 | 39.44 |
| Responses with list markers (%) | 19.44 | 61.67 | 33.33 |
| Responses with code fences (%) | 5.00 | 0.00 | 23.89 |
| Responses with bold markers (%) | 25.56 | 19.44 | 46.67 |

Lexical diversity was measured using the **moving-average type-token ratio with 50-word windows (MATTR-50)**.

MATTR-50 provides a measure of vocabulary variation while reducing some of the response-length dependence associated with ordinary type-token ratio.

#### Main Observations

**Claude**

Claude generated the longest responses, averaging approximately 630 words.

It used list markers in 61.67% of responses, the highest frequency among the three models.

Claude also had the lowest mean MATTR-50 lexical-diversity score.

**Gemini**

Gemini produced the shortest responses, averaging approximately 329 words.

It used heading markers in 39.44% of responses, code fences in 23.89%, and bold markers in 46.67%, the highest frequencies for these formatting characteristics.

Gemini also had the highest punctuation/symbol count per 100 words.

**GPT**

GPT generated responses averaging approximately 459 words.

It used heading markers in 30.56% of responses.

Its mean lexical-diversity score was close to Gemini's and higher than Claude's.

#### Interpretation

The analysis revealed measurable differences in response length, lexical diversity, punctuation, and formatting across the three LLM families.

These characteristics may provide useful signals for distinguishing model-generated responses.

However, RQ4 is a **descriptive analysis**. It does not establish that the CNN or LSTM relied on these particular features when making predictions.

No separate feature-ablation or statistical-significance experiment was conducted to determine the causal importance of individual writing characteristics.

## Limitations

Although the project produced meaningful results, several limitations should be considered.

**Dataset size:** The dataset contains 540 responses from 180 prompts, which is relatively small for neural text classification.

**Model coverage:** The project evaluates three LLM families and the specific versions used during dataset collection. Results may differ for other models or versions.

**Subject coverage:** The dataset contains six selected subject categories and does not represent every possible writing task.

**Response characteristics:** Classification may be influenced by response length, formatting, punctuation, vocabulary, and other properties associated with the dataset's generation conditions.

**Architecture selection:** Only one primary CNN architecture and one primary LSTM architecture were evaluated. Different architectures or hyperparameters could produce different results.

**Checkpoint selection:** The CNN and LSTM used different validation criteria for selecting their primary RQ1 checkpoints.

**Evaluation variability:** The primary test set contains 81 responses. Repeated experiments using additional random seeds or alternative prompt-grouped splits could provide more reliable estimates of performance variability.

**Cross-domain evaluation:** General writing was the only held-out category. A complete leave-one-category-out evaluation was not performed.

**Writing-style interpretation:** RQ4 identifies descriptive differences but does not establish which characteristics caused particular classifier predictions.

**Authorship certainty:** Classifier predictions reflect statistical patterns in the evaluated dataset. They do not provide definitive proof of authorship.

## Future Work

Future improvements could include:

- Expanding the dataset with more prompts and additional subject categories.
- Evaluating additional LLM families and different versions of the same model.
- Comparing CNN and LSTM performance with transformer-based text classifiers.
- Performing leave-one-category-out cross-domain evaluation.
- Testing multiple random seeds and repeated train-validation-test splits.
- Investigating the effects of response length and sequence truncation.
- Studying the contribution of individual linguistic and formatting features through feature-ablation experiments.
- Examining whether model-identification accuracy remains stable as LLM versions change.

These extensions would provide a broader understanding of the reliability and generalizability of LLM authorship classification.

## Conclusion

This project demonstrates that neural-network classifiers can identify the source of LLM-generated responses with accuracy substantially above the three-class chance baseline.

Using an original dataset of 540 responses from GPT, Claude, and Gemini, we implemented and compared CNN and LSTM classifiers across multiple experimental settings.

The CNN achieved **82.72% accuracy** on the primary output-only classification task, compared with **71.60%** for the LSTM.

Our experiments also showed that using generated responses alone produced stronger classification performance than using original prompts or combining prompts with responses.

In the cross-domain experiment, the CNN achieved **72.22% accuracy** on unseen general-writing responses, while the LSTM achieved **56.67%**.

The writing-style analysis further identified measurable differences in response length, lexical diversity, punctuation, and formatting across the three model families.

Overall, the results support the feasibility of automated LLM authorship classification within our experimental setting, while emphasizing the importance of careful dataset construction, evaluation methodology, and testing across unfamiliar domains.
